# Office 依赖与影响分析扩展

扩展名为 `ppt2wiki.impact`，扩展版本为 `1.0.0`，放在 `ChangeSet.extensions`。机器定义见 [office-impact.v1.schema.json](../schemas/office-impact.v1.schema.json)。它使用现有 Office Change `1.0.0` 的对象身份、值类型和源文件定位器。核心 `changes` 继续记录两个输入文件快照中已经识别出的事实差异；本扩展记录相关对象、前后依赖、影响判断和证据。

本扩展是正式协议约定。前文讨论过的 `ppt2wiki.formulaResult` 草案未采用，不能与本扩展混用。比较器、展示器、LLM 输入适配器与原文件标记者应分别声明是否支持本扩展版本。演示比较器现已比较公式的已保存结果，并生成普通单元格、范围和跨工作表引用的静态影响分析；尚未接入计算引擎，因此不会声明已验证因果或凭相同缓存确认结果未变。

演示比较器只对已保存结果变化、公式修改或存在已知变化传播路径的单元格生成影响记录。引用解析不完整本身只记录为 `coverage.dependencies` 的分析缺口，不因文件其他位置发生变化而生成 `unknown` 影响。展示器在“分析限制”中单独提示这些缺口，不计入计算影响数量。

## 一个范围公式变化的完整含义

旧版 A5 为 10，新版 A5 为 20；B1 的公式始终是 `SUM(A1:A10)`，已保存的计算结果从 100 变成 110。对应数据包括：

1. 核心 `changes` 中两条 `value` 更新，分别表示 A5 和 B1 的前后值；开启 `comparison.compareCachedFormulaValues`。
2. `entities` 登记 A5、B1 和所属工作表，各自保存前后锚点；B1 保存两版相同的公式上下文及结果值来源。
3. `dependencies` 中一条 B1 对 A1:A10 的引用，分别保存旧版和新版的范围，以及本次分析涉及的 A5 身份。
4. `impacts` 中一条 B1 结果变化的判断，`changeIds` 指向 B1 的变化，`causes` 指向 A5 的变化，并通过 `dependencyIds` 指出传播路径。
5. `evidence` 说明判断是静态推断、证据支持还是因果验证；计算记录及控制回放报告为较强结论提供依据。

可读取完整的 [范围与连锁变化示例](../examples/excel-range-impact.changes.json)。示例还包含 C1 对 B1 的引用，展示 A5 → B1 → C1 的传播。

## 顶层字段

| 字段 | 含义 |
| --- | --- |
| `version` | 扩展版本，固定为 `1.0.0` |
| `scope` | 本次影响分析的目标 `entityIds` 和请求分析的 `mechanisms` |
| `entities` | 最小相关对象登记表，包含参与者和必要的上下文对象，不是整个文档模型 |
| `dependencies` | 按前后快照分别记录的静态引用关系 |
| `computations` | 绑定输入文件快照的计算或渲染输出及环境、引擎和证据摘要 |
| `impacts` | 目标属性的影响判断、候选或确认原因、对应变化与证据等级 |
| `lineages` | 拆分与合并的对象对应关系 |
| `coverage` | 依赖解析、原因确认、计算与结构分析分别报告覆盖情况 |
| `delivery` | 分析记录是否完整交付，以及各类被省略记录的准确数量 |

分析范围与核心 `comparison.aspects` 分开。例如核心值比较可以完整，而原因确认不完整。`scope.entityIds` 是需要作出影响判断的目标；登记表还可包含范围所属工作表、未变化的输入、路径中的中间对象等上下文。`impacts` 不得超出声明的目标和机制范围。`complete` 只适用于本次声明的范围，不表示整份文档所有关系都已经识别。

## 对象身份与前后状态

每个 entity 包含 `entityId`、`kind`、`label`、`before` 和 `after`。ID 使用核心协议的比较内身份空间；同一个对象跨地址、跨位置变化仍使用同一个 ID，不得把地址当作身份。至少有一侧状态存在；不存在的一侧为 `null`。未变化但参与依赖的对象也可登记，无需伪造一个 Change。

状态包含：

- `source`：所属原始文件快照内的定位器。复用核心约束，地址只在该快照中有效。
- `formula`：可选的 OOXML 公式上下文，无前导等号；`null` 表示对象存在但没有公式。缺少字段表示未提供公式上下文。
- `observations`：本次分析读取的属性及其值、可用性、来源和新鲜度。同一侧同一属性只能有一条。
- `display`：可选的用户可见文本，仅用于说明显示变化；它不是数值或定位依据。

登记表与相关核心 Change 的 kind、两侧锚点和已保存属性值必须一致。公式上下文存在时，也须与相关公式变化一致。共享公式无法展开时应省略未知的公式文本，并提供 dynamic/unresolved 依赖及覆盖缺口；此类记录只能给出未确认的影响判断，不得伪造空公式或声明已验证因果。公式被替换为常量而结果相同，仍由核心 `formula` 事件表示；如需解释其他连带结果，可把这条公式变化作为原因。

## 值、缓存、重算与不可用

每条 observation 有 `property`、`status`、`origin`、`freshness`：

| 字段值 | 含义与约束 |
| --- | --- |
| `status: known` | 值已经取得，必须提供 `value`；已知空值仍用核心 null 值 |
| `status: unavailable` | 未能取得结果，不得提供 `value`，不能用 null、0 或空字符串代替 |
| `origin: literal` | 从原文件规范语义中提取的非缓存值；新鲜度为 `notApplicable` |
| `origin: storedCache` | 原文件保存的公式或字段缓存；新鲜度为 `verified`、`unverified` 或 `stale` |
| `origin: recalculated` | 额外计算得到的值；必须绑定同侧 computation，输出吻合，且为已知、已验证状态 |
| `origin: rendered` | 额外渲染得到的属性；绑定与重算相同的证据规则 |

`freshness: verified` 的缓存需要同侧 computation 复现相同值；这只证明缓存与该计算记录一致，不能单独证明因果。声明 `stale` 或 `unavailable` 时，计算分析若在请求范围内，必须报告相应缺口。错误结果用已有的 `error` 值表达，不能与“未能计算”混淆。

公式、精确数值与显示文本分别比较。数值变化可能因显示精度而不可见；格式变化也可能使相同数值显示不同。展示层应说明具体变化维度，不能只根据 `display` 判断数值是否变化。

### 原始快照与额外计算的边界

核心 `documents` 的摘要绑定原始输入文件。重算值如果并未保存于这些输入文件中，不得填进核心 Change 的 before/after，冒充原文件值。

- 比较原文件保存的缓存值时，按已有规则显式启用 `compareCachedFormulaValues`，生成核心 `value` 事件；缓存新鲜度另行说明。
- 额外计算的结果记录在 observation 和 computation 中。它们可以支持 `outcome: changed` 的影响判断，但不增加原始文件的核心变化事件。
- 若产品要把重算后的文件作为比较依据，应显式生成两份新快照并重新计算摘要；原文件和派生文件的绑定不能混用。
- 原文件高亮仍使用原始锚点。可以标记计算影响对象并注明“重算分析”，不得将重算值写回原始单元格来制造差异。数值、公式的标记仍以单元格为单位。

完整示例见 [额外重算分析](../examples/excel-derived-impact.changes.json)。

## 引用、范围与依赖变化

一条 dependency 包含 `id`、`dependentEntityId` 和前后两侧的 reference。方向为“输入 → dependent”，不是数组执行顺序。至少一侧引用存在。每侧均包括 `kind`、`expression`、`resolution`、`members`：

- `kind` 支持 `cell`、`range`、`name`、`table`、`dynamic`、`external`、`object` 和 `environment`。
- `expression` 保留用于说明和核对的引用表达式；表达式文字相同不保证解析到相同对象。
- `resolution` 为 `resolved`、`partial` 或 `unresolved`。未完全解析必须报告依赖覆盖缺口，不得当作无依赖。
- `members` 列出本次分析涉及且已登记的被引用对象，不承诺枚举整个范围全部单元格。
- `areas` 保存已解析的矩形区域，每个区域使用工作表 `sheetEntityId` 以及闭区间 `start`、`end`；支持多区域、跨表，不展开整列或大范围。整列等表达式由适配器转为有边界的区域。
- `external` 在外部引用时必填，使用名称和内容指纹标识外部输入版本。拿不到其内容时必须报告缺口。

已解析的 range 必须提供 areas。区域边界不超过 XFD1048576，起点不得大于终点；涉及的单元格成员必须位于同侧同表的相应区域中。`areas` 是解析结果，表达式是否真的解析到这些区域由原文件适配器验证。

前后引用分别解析，因此可以表示插行后 A5 变为 A6、范围扩张、命名范围重定向，以及某一侧才出现的依赖。只在旧版成立和只在新版成立的边，不能拼成一条不存在于任一版本中的传播路径。

引用范围新增成员、删除成员或改变目标也能成为原因。对应 cause 使用 `kind: dependency` 和 `dependencyId`，随后使用 `dependencyIds` 继续传播。只丰富 `members` 的分析清单或将 resolution 从未解析变为已解析，不属于引用本身变化，不能据此声称计算结果变化。见 [命名范围变化示例](../examples/excel-reference-impact.changes.json)。

静态依赖可以有环。消费者遍历时应使用已访问集合并报告无法处理的循环计算；协议不要求把所有依赖强行变成有向无环图，也不从数组顺序推导重算顺序。

## 影响与原因

impact 通过 `entityId` 和 `property` 指向需要判断的属性。机制 `mechanism` 支持公式、字段、图表、样式继承、布局和外部刷新。所有机制共用对象、引用、结果及证据模型，不为 Excel 单独构造另一套因果协议。

`outcome` 为：

| 值 | 含义 |
| --- | --- |
| `changed` | 目标已有对应的核心属性更新，或两侧可信的额外计算结果确实不同 |
| `unchanged` | 两侧可信观察值相同，仍可记录参与重算或受影响的事实 |
| `unknown` | 结果尚不能确认；不能解读为结果相同或没有影响 |

`changeIds` 必须准确列出已交付的目标属性更新。没有原始文件变化时为空。存在目标属性更新就必须标为 changed；unchanged 和 unknown 不得产生相等值的伪造 update。观察值、核心事件和结论不得互相矛盾。

`causes` 允许多个来源：

| kind | 字段与用途 |
| --- | --- |
| `change` | `changeId` 指向输入、公式、样式或结构等核心变化；`dependencyIds` 按原因对象到目标对象的顺序列出路径 |
| `dependency` | `dependencyId` 指向本身已变化的引用，随后 `dependencyIds` 描述继续传播的路径 |
| `environment` | `name`、`before`、`after` 描述时钟、外部数据、引擎或设置等环境变化；两侧必须不同 |
| `unresolved` | `detail` 说明尚未确定的来源，原因确认覆盖必须为 partial |

自身的公式或其他属性变化作为原因时，路径可以为空。跨对象原因必须有能连通目标的路径。一个结果变化事件不能成为自己的原因。

原因清单在低证据等级下表示候选原因。多输入同时变化时，除非控制回放证据证明，否则不能宣称“只有 A 导致 B”，也不能按变化金额比例自动分摊贡献。`A → B → C` 可以由两个直接影响记录连接，也可以在 C 的 cause 中列出完整路径；展示可以追溯根来源，但不得将两种表示重复计为不同事实变化。

两个输入变化相互抵消时，记录 unchanged 的影响及多个触发输入，不生成目标 value 更新。此时“已验证”说明这些输入参与本次计算且结果保持相同，并不声称结果发生了变化。见 [输入抵消示例](../examples/excel-compensated-impact.changes.json)。

## 证据等级与计算记录

| `evidence.level` | 允许的解释 |
| --- | --- |
| `potential` | 静态引用等信息表明可能受影响，不能作出已确认因果结论 |
| `supported` | 已观察到差异且存在支持性的依赖或执行信息，尚未完成因果验证 |
| `verified` | 生产者报告完成了控制回放，具有独立报告摘要及两侧结果复现记录 |

`method` 可为 `staticAnalysis`、`snapshotComparison`、`executionTrace`、`controlledReplay` 或 `structuralComparison`。verified 只能使用 controlledReplay，须有 `artifactSha256`，并引用恰好一条旧版和一条新版的 computation。两侧结果可靠、输出与目标吻合，所有已声明原因明确，相关依赖路径已解析。只发现公式包含 A、只重算一次、只记录执行读取了 A，均不足以自动升级为已验证因果。

控制回放报告应明确被改变的输入集合、保持不变的条件、公式与引用是否变化、对照运行结果、遗漏输入的排查范围；按多个来源共同触发的结论验证，不要求不成立的逐输入独占归因。报告可以独立存储，以其内容 SHA256 与协议绑定。

computation 包含：

- `side` 和 `inputSha256`：明确输入文件快照；必须与对应 documents 摘要一致。
- `engine.name/version`：计算或渲染引擎身份。
- `contextSha256`：计算环境的规范清单摘要，覆盖固定时间、区域、设置、外部输入指纹等，排除文档输入字节、运行日志与输出值；使用 UTF8、键排序、无多余空白的 JSON 编码生成。具体清单随证据报告保存。
- `environment`：可选的具名外部输入及其内容指纹，名称唯一；数组顺序不代表环境变化。
- `artifactSha256`：本次计算证据工件内容的摘要。
- `outputs`：对象、属性和值。一个计算记录内不得重复对象与属性。

用于 verified 结论的前后引擎或环境不同时，必须分别增加 `name: engine` 或 `name: context` 的环境原因，并在回放报告中解释。未知环境漂移必须降低结论并报告缺口。

JSON Schema 和本地语义校验只能验证这些声明的结构、一致性和引用完整性。它们不能凭一个哈希证明报告真实、公式依赖正确或因果已验证。原文件适配器和证据审核器负责核对文件、执行结果、报告摘要以及控制回放有效性。

## 拆分、合并与批量影响

lineage 的 kind 为 `split` 或 `merge`。split 是一个旧对象对应多个新对象，merge 是多个旧对象对应一个新对象。两侧身份必须独立，旧对象在新版不存在，新对象在旧版不存在；每个实体仍遵守核心增删互斥规则。核心可记录相应新增、删除，lineage 提供结构上的对应关系，不宣称恢复了真实编辑步骤。见 [段落拆分示例](../examples/word-split-impact.changes.json)。

大量派生变化仍各自保留事实事件。界面可以按来源、范围或结构对应关系汇总，但分组不增加事件，也不把原因记录数加到变化数里。统计应分别报告核心事实事件数、受影响对象去重数和影响判断数；结构操作数量单独统计。

`delivery.status` 为 complete 时，所有 omitted 计数必须为零；为 truncated 时，至少一个计数大于零，相关分析覆盖必须包含 truncatedContent 缺口。省略数量针对分析记录，不是核心 Change 数量。保留的分析子图必须引用闭合：不能省略仍被引用的实体、依赖、计算或原因事件。对尚不能确定被省略数量的生产者，应先结束分析并报告范围缺口，不能以零伪称完整。

## 覆盖与消费规则

依赖解析 `dependencies`、原因确认 `attribution`、计算 `computation`、结构 `structure` 各自使用 complete、partial、notRequested。partial 必须列出问题，其他状态的 issues 必须为空；notRequested 不得同时输出该类分析记录。

未确认的原因或未知结果必须使 attribution 为 partial。缺口支持不支持的引用、引用未解析、结果不可用、缓存过期、外部内容缺失、原因未验证、匹配未解决与记录截断，并可指向已登记对象。缓存值比较完整，不等于计算或原因确认完整。见 [无法确认计算结果示例](../examples/excel-unknown-impact.changes.json)。

未知扩展版本不得按已支持版本解释。只支持核心协议的消费者可以继续展示核心事实差异，但必须说明未解析影响分析，不能声称已展示完整原因。支持本扩展的消费者应按以下方式说明结果：

- verified 且 changed：在证据审核通过后，说明已确认来源及结果变化。
- supported 或 potential：展示实际差异或可能影响，同时保留“原因未确认”的措辞。
- unchanged：说明已检查的连带影响及结果相同，使用独立的影响提示。
- unknown：说明结果尚未确认，并提供对应覆盖缺口。

颜色、边框等展示策略仍由消费者决定；协议约束事实、关系与结论强度。

## 校验与示例维护

运行 `python scripts/validate_change_protocol.py --self-test`，同时检查核心协议与本扩展。已有依赖目录时可提供 `--dependency-dir`。验证器自动识别 ChangeSet 级的 `ppt2wiki.impact`，拒绝未知版本、悬空引用、跨版本拼接路径、错误范围、计算快照不一致、未验证结果冒充已确认结论等情况。

`python scripts/impact_examples.py` 可重新生成七份合成示例。所有摘要、计算记录和控制回放声明均为说明协议的占位内容，没有对应的真实 Office 文件或计算报告。示例通过本地校验不代表真实执行了重算或因果验证。

静态前端构建会分发本扩展的 Schema。演示页面已提供计算结果标签、计算影响入口、来源与后续影响定位、按需引用范围展示；额外重算值通过影响明细呈现，预览保留文件原值。后续可补充命名、动态、外部引用的解析，以及独立计算和因果回放证据。
